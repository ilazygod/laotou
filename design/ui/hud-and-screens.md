执行依据：历史 `Claude-Code-Game-Studios-Codex` 的 `docs/codex/runtime.md`、`team-ui/SKILL.md`、`ux-review/SKILL.md`、`ui-programmer.md`、`ux-designer.md`、`ui-code.md`，并参考 HUD 模板与项目 Art Bible 1.0。采用顺序 UX → UI 实现 → 自查角色 pass；未声称独立总监或无障碍审核完成。用户本轮无人值守、自主合理细节和文件制作授权优先于模板反复问询要求。

## 玩家需求与信息预算

玩家在高速踏空和飞镖间作判断，战斗中心必须保持留白。底部信息带始终提供击杀、生命、蓄势三项信息；第四项就绪提示仅在绝杀可用时出现。称号只在升级后显示 2.4 秒，结算时正式呈现。无测试工具条，无常驻左右大按钮。

主目标 390×844；兼顾 320×568、375×812、430×932 与桌面。保留原 v33 触控区底边 G 与所有模拟参数。因真实尸体接地线为 G+23，新的下方纸幅固定90px高，从 G+26 开始，接地线前后3px保持可见，避免画面看似尸体悬空。安全区较大的实机仍需浏览器走查，不能因此暗改 G 或物理。

## 屏幕流

1. 标题：画面上端题名「白眉老头 / 忍者雨」，单枚朱红「墨」章；人物维持原开场镜头中心；底部 48px 以上「入江湖」入口。
2. 点击原 `startGame` → 原 `reset()` / `setIntro('ignite')`，燃目 0.72 秒 → 镜头回收 1.15 秒 → 原 `openingWave()` 的 16 名忍者按各自 delay 入场。
3. 教学：保留 tutorial 状态、原双按190ms窗口；提示改为「同时按住左右半屏」。不改变输入判定。
4. 开场绝杀：保留 openingUlt 全过程，进入 play。
5. 战斗：原左右半屏指针监听和反馈 class；新的窄朱红侧边反馈不挡住角色。
6. 战败：DOM 浅纸结算呈现原阈值称号、斩数、距下一称号数；「再战一回」只发 `studio-command`，整合层调用现有 `jump(hero.face)`，保持原重开行为。原点击任意侧重开继续可用。

## 数据与视觉

| 元素 | 来源 / 所有权 | 呈现 |
|---|---|---|
| 斩数 | game.count | Georgia 可读数字 43px + 斩 |
| 生命 | game.hp | 3枚21px朱红「命」印，失去后为空框；另提供文本 aria-label |
| 四档蓄势 | game.kicks / tier | 5px墨线、3/12与7/12刻度、一至四重文字，12次就绪 |
| 绝杀提示 | game.ultReady | 下方信息区中间，朱红「双按·绝杀」 |
| 称号 | 原 rank thresholds | 短暂顶部题签，2.4秒；结算完整显示 |
| 游戏结束 | game.dead / intro | 仅 play+dead 打开结算 |

UI 只读状态，缓存 DOM 更新，无每帧反复 innerHTML、无模拟写入、无音频调用。所有操作经现有入口或 command event 交给游戏层。

配色按 Art Bible：纸 #f6f2e8、浓墨 #242321、正文灰 #68675f、朱红 #a54e3b。字体采用 Songti SC / STSong / Noto Serif CJK SC / SimSun / serif，本机缺字时安全回退，不下载字体。墨印是 UI 排版元素，不作为新绘制的角色或特效美术资产。

## 可访问性与边界

- 正文最小13px；击杀和结果数字使用清晰数字字体。
- 实算纸底对比：浓墨14.05、正文灰5.09、朱红5.01，均通过4.5:1。
- 生命通过实心/空框区别，不只依赖颜色；蓄势同时显示档位及数字。
- Start/Retry 为原生 button，Tab/Enter/Space 可用；清晰 focus-visible 边框，尺寸≥48px。
- prefers-reduced-motion 关闭 HUD 过渡；不改变已通过的开场与战斗动画。
- UI 文本集中在 `studioUi.strings` 和同模块称号表；本轮只交付中文。
- 原项目没有手柄输入。本模块未改动控制器逻辑、未宣称手柄支持或完整无障碍符合性。需将此列为未测试而不是 PASS。
- 无独立玩家旅程或交互模式库现成文件，本轮按实际 v33 行为补录以下模式，不推测玩法。

## 交互模式补录

| 模式 | 适用状态 | 规则 |
