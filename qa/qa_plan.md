## 自动执行

脚本：`work/studio_v1/qa/run_vm.cjs`。读取交付 `playtest.html` 的同一份游戏代码，在 Node VM 与原生 Canvas 上执行，固定随机数与模拟时钟。所有测试显式 Arrange / Act / Assert，逐用例清空模拟状态。脚本不写正式 HTML，不调用浏览器，不更改冻结资产。

报告：`qa/vm_validation.json`；包含最终 HTML 的 SHA256，任何重建后必须重跑，否则证据对应旧构建。`qa/vm_status.json` 只表明本套测试状态，不代表全部验收。

性能阈值：宿主 VM 模拟更新 P99 <16.67ms。这个阈值只限制 CPU 模拟代码，不声称手机/GPU达到60FPS。截图 `vm_*.png` 只有 Canvas，没有实际DOM，不能用来证明UI布局合格。

## 特别约束

- v33 本来采用剑光**端点**接触弹反、相对连续轨迹判断人体伤害。测试分别验证两者；不把端点弹反伪称连续弹反。
- 尸体模拟继续用原支撑代理；视觉层对齐到实际墨迹外轮廓。自动测试既验证模拟接地，又逐张渲染三色上下半身、五个角度扫描 alpha，验证实际画面与 G+23 的差距。
- 水墨消散的自动测试对真正纹理像素分四个角区读取透明度质量，验证峰值逐区出现且旧尾端先消失；不依赖元数据或源码字符串来声称视觉效果正确。
- 浏览器输入、手机安全区、游戏手柄和人工美感均不由 VM 的 PASS 代替。

## 发布判定

S1：无法启动、开场卡死、状态NaN或资产丢失；S2：碰撞/取消/双按回归、明显悬空尸体；S3：UI溢出、局部笔触瑕疵；S4：非阻断排版优化。

自动 Logic/Integration 失败时不得声称对应项目完成。Visual/Feel 需正常速度实际 Game View 证据且仍标「待用户审美验收」。当前没有目标手机硬件实测，不得声称手机性能全面通过。
